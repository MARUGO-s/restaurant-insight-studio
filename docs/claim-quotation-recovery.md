# 主張引用の書式復旧と統合のみの承認再生成

## 状態

本番公開済み。ユーザーは「完了済み4専門調査を維持した統合1回分の追加生成」と完成後の本番反映を明示承認した。134件の統合回帰・独立レビュー後に公開し、Pagesと両Functionの配布一致を確認した。承認済みの実統合1回と保存応答の無料再検査で復旧し、本番の完了状態・品質v3レポート1件の保存を読み戻した。公開と解析結果の詳細は [公開記録](release-synthesis-recovery-2026-11-01.md) を参照。

## 確認した原因

本番の失敗ジョブを読み取り専用で取得し、実際のworker処理をネットワーク禁止・DB境界モックで再生すると、元のclaimReviewsエラーを再現した。保存応答33件の主張審査のうち2件は、専門原文の太字記号だけが省略されていた。本文の内容差ではなく、raw Markdownと表示文字列の差である。

詳細診断では別に3件の審査出典が観測済みURL台帳と一致しないことも判明した。Google提供の記録済みリダイレクト17件を読み取り確認しても、そのURLの同一性を裏付ける対応は得られなかった。ドメインと記事IDの似た別URLを同一資料として補完してはならない。太字の問題だけを解消して今回の解析全体が完成すると説明しない。

実レポート・店舗名・実行ID・認証情報は、この文書や公開テストへ転記しない。取得データはHermes scratch内に隔離する。

## 無料の引用復旧契約

- 同じ担当の原文に一意に対応する、対になった太字（`**`）・斜体（`*`）記号の省略だけを復元する。復元先は原文の連続する部分そのものとする。
- 数字・否定・空白・句読点・意味の言い換えは修正しない。他担当への付け替え、曖昧な複数候補、コード・URL中のアスタリスクの除去は許可しない。通常の末尾引用リンクや無関係な別行のコードで担当原文全体を拒否しない。入れ子リストは連続するASCII親リストで証明できる相対インデントだけを許可し、親のない字下げやコード相当のインデントは除外する。区切りの前後文字はUnicodeコードポイントで判定する。
- 専門調査と保存済み統合原稿を保持する。復元前後の引用、field path、種別、原稿SHA-256、追加生成0をサーバー所有の監査情報として生成する。
- 復元後も品質v3、出典追跡、主張の重複、未採用主張の再断定、商品・分類検査を通す。検査不合格なら完成扱いにせず原稿を残して停止する。
- エラーを `claimReviews[index].field` 単位にする。引用、担当、採否、理由、出典、重複のどこで止まったか区別する。
- 新規統合プロンプトへ担当別の記録済みURL台帳を渡し、Markdown記号の原文保持、ドメイン・記事番号の推測による組み替え禁止、未取得ページを根拠として扱わないことを明示する。台帳は取得本文や主張の真偽を保証しない。
- OpenAI Responsesへの新規統合要求に `include: ['web_search_call.action.sources']` を明示し、実際のtool出典を保存する。生成JSONのURLを取得証拠へ昇格しない。

## 統合だけを1回再生成する契約

1. 対象は同じ所有者の失敗run。4専門調査が完了し、統合にcompleted応答と `sourceRecovery.status = needs_review` があり、完成レポートがなく、削除状態でない場合のみ許可する。
2. `run_status` は `canRegenerateSynthesis` と `synthesisRevision` を返す。画面の「統合だけ作り直す（追加API料金）」は4調査保持・統合1回・金額未確定・自動再生成なしを確認する。通常の保存応答再確認とは別操作。
3. `regenerate_synthesis` は認証所有者に対して `runId`、UUID `requestId`、`expectedRevision`、厳密な `confirmAdditionalCost: true` を要求する。確認フラグは人が読んだことの技術的証明ではない。
4. `restaurant_insight_regenerate_synthesis` はservice_role専用。所有者advisory lock→run→jobの順で排他し、保存済み応答IDと同意revisionを照合する。同じrequestIdの再送は同じ世代を返し、古い画面の同意で次の応答への新規購入を許可しない。
5. 元の統合output・検証理由は `restaurant_insight_synthesis_regenerations` に保存する。RLSで本人のみ読取、通常の変更・削除を許可しない。既存の「レポート完全削除」では関連jobと一緒に削除される。
6. 4専門調査と既存料金行は変更せず、統合のみpendingへ戻す。サーバー所有の `regenerationId` で世代を分け、品質v3を保持する。
7. 同じjob＋generationのAPI試行予約はunique indexで1件だけ。unknown・partial・failedでも2回目の購入へ進まない。同世代の本人・run・job・responseIdが一致する完成応答だけ無料で再利用する。提供元が課金したか不明な場合を0ドル扱いしない。
8. ブラウザはuser＋run＋revisionごとにUUIDを保持し、応答不明や再読込で再利用する。保存不能・不正IDでは送信しない。同期refロックで連打・通常retry・確認・閉じるとの競合を防ぐ。

未知出典を勝手に削除・差し替えたり、supportedを自動で未確認へ変えたりして完成扱いにしない。新しい応答も両品質ゲートに合格する必要があり、有料再生成1回は完成を保証しない。不合格なら勝手にもう1回生成せず停止する。
